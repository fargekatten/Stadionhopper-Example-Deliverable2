# Stadionhopper – Example Deliverable 2

This repository is an example of how a strong exam submission for IBE205 could be structured and documented in GitHub. The goal is not to present a finished product, but to show a clear technical and organizational foundation for further development of Stadionhopper.

The examples in this repository are deliberately written as a high-quality reference solution. They are meant to help you understand how to:

- model the domain
- explain the architecture
- justify design decisions
- document UX and wireframes
- describe Git strategy
- plan CI/CD and testing

This repository demonstrates a Git-based “technical trace”: each topic is represented as a Markdown file in the repository, making it easy to review, discuss, and merge as part of a realistic development workflow.

## Repository structure

- `README.md` – overview of the example and how it maps to the exam task
- `docs/01-domene-model.md` – domain model and relationships
- `docs/02-arkitektur.md` – architecture and technical decisions
- `docs/03-ux-wireframes.md` – UX, personas and wireframes
- `docs/04-git-strategi.md` – branching, pull requests and collaboration
- `docs/05-test-strategi.md` – testing strategy and quality assurance
- `docs/06-issue-plan.md` – example GitHub issue breakdown

## Why this is a strong example

This example is intentionally written to match the exam requirements:

- it explains not only what the system should contain, but why
- it connects product goals to technical decisions
- it shows that architecture, UX, process and testing are integrated
- it demonstrates a practical Git workflow so the work is visible in version control

## Important note

This repository is an educational example. In a real exam submission, the team should still adapt the wording, diagrams, and technical choices to the actual project conditions, available technology and the team’s own decisions.
